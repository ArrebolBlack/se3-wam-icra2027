## 4. 进行中：协议时间线单栏图（§4.3）

- 当前草稿是 `fig4_study/panel_timeline.png`，脚本在 `scripts/fig4_panels.py` 的 `timeline()`，分两组对比：
  - 暂停世界：推理 152 ms 期间物理时钟停止，之后从第 1 条指令开始执行；
  - OnTimeBench 原生延迟：物理时钟按 50 ms 的控制周期持续前进；上一个动作块继续执行，新动作块在推理结束后的第一个周期边界接管（k = ⌈L/Δa⌉ = 4），前 k 条指令已过期，跳过。
- 协议的事实依据在 `appendix/benchmark.tex` 和 `sections/benchmark.tex` §4.3：
  - 物理按每个方法、每次查询的实测延迟推进；
  - 所有方法共用同一个执行器；
  - 第一个动作块到达之前，执行器保持当前目标；
  - 如果 k ≥ H，整个动作块丢弃；
  - post-impact 任务有 d_task = 50 ms 的执行延迟。
- **v2 草稿（2026-11-16）**：`fig4_study/fig_timeline_v2.png`，脚本 `scripts/fig_timeline_v2.py`，单栏 3.25 × 2.7 in。分三条泳道，共用一条物理时间轴（0–450 ms，网格为 50 ms 控制周期）：
  1. Paused（参照）：推理不占物理时间，每 50 ms 重新规划一次，执行新动作块的第 0 条指令；
  2. Native 快策略（p95 15 ms，k = 1）：每个周期发起一次查询，第一个周期保持（hold），之后每个周期执行最新动作块的第 1 条指令；
  3. Native 慢策略（p95 152 ms，k = 4）：第一个动作块的第 0–3 条指令过期跳过，200 ms 之前保持，200–400 ms 执行第 4–7 条，400 ms 起由第二个动作块（于 200 ms 采集）从第 4 条接管。
  - 配色：观测为蓝，推理为灰，指令为琥珀黄（相邻两个动作块用深浅区分），Paused 的标题用红色，Native 用绿色，与 Fig. 4(a) 一致。
  - **需作者确认**：(i) 原生协议下，下一次查询是在“交接边界”采集，还是在“推理结束时”立即采集？appendix 原文是 “hands over … The policy then observes again”，草稿按交接边界画。(ii) 草稿用固定的 p95 延迟作示意；实际是每次查询从实测分布中抽样，图注需要说明。(iii) k ≥ H 时整块丢弃，以及 post-impact 任务的 d_task，草稿都没有画，打算写进图注。
