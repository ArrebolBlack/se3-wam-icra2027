## 1. 一页看懂新稿

**一句话主张。** 动态操作的指令必须与它生效时刻的场景相符。位置误差的恒等分解经三角不等式给出预算上界，包含定位、领先时长 × 速度误差、
速度 × 时间误差和未被匀速外推解释的动力学；接触误差还受旋转项影响。预测路径若保持间隙 $m$，碰撞要求某处环境预测误差至少达到 $m$。这些关系用于误差预算，不是成功率模型；在所列假设下提出定量预测，
由此得到三条原则：

| 原则 | 分解中的项 | 定量预测（表 1） | 模型中的实现 | 检验（第 5.3 节） |
|---|---|---|---|---|
| 整体 | $\|v\|\Delta/\varepsilon$ | 忽略运动的策略预计在未补偿运动超过容差后失败；检验按此比值归一化的成功率曲线 | — | 图 4a |
| 记住 | $\hat\Delta e_v$；$e_v(\sigma)$ | 历史在临界领先时长 $\ell^\star=\varepsilon/\|v\|$ 之后起作用；价值保持到 $\sigma^\star=\varepsilon T\sqrt n/(\Delta\sqrt{12})$ | 因果跟踪器的 SE(3) 历史（8 个 token），不输入过去图像 | 表 3、图 4b/4c |
| 预测 | $e_{\rm dyn}$、$r\theta$；$m$ | 学习的 SE(3) 未来在非匀速运动上胜过外推；粗流在间隙 ≥ 其路径误差 $e_F$ 时足够 | 物体查询回归目标 SE(3) 轨迹，场景查询回归 14×14 网格点的 3D 位移与可见性（确定性，带角色嵌入）；未来 depth / DINO / 动态区域 RGB 只作训练目标 | 表 3、图 4d/4e |
| 行动 | $\|v\|e_\tau$ | 时域错位代价 ∝ 速度；按控制步计的领先时长在延迟变化时失效 | 物理时间索引；领先时长嵌入；训练延迟 $\ell\sim U[0,250]$ ms；动作用流匹配（5 步 Euler）；掩码 $\mathcal G$ 定义耦合程序 R0–R5（与 Research Q3-INFO0 一致） | 表 3、表 4、图 4f |

## 2. 结论开关（`paper_config.tex`）

所有随实验结论变化的表述都写成了开关，改一个数字即可整体切换（正文、摘要、图注、表中的 ★ 选中标记、

### `\QtwoCase`：环境的表示与分辨率（对应旧 Q2）

| 值 | 含义（判定标准） | 新稿主张 |
|---|---|---|
| 1（默认，预期） | 目标 SE(3) + 粗 3D 流最好；$28^2$/$56^2$ 网格只在间隙降到粗流路径误差 $e_F$ 附近时更好 | "目标精确预测，环境只需预测到其间隙所需的精度" |
| 2 | 度量 3D 未来优于图像空间未来，但在所扫描的最窄间隙（仍高于 $e_F$）下分辨率也无可测影响 | "关键是度量 3D；环境分辨率次要" |

### 结果不落在任何预设情况时

开关覆盖了最可能的结局；若出现以下情况，按"分解仍成立、经验结论换一种说法"的方向最小改写，不要回退到"实验顺序"写法：

- **视觉历史也有明显帮助**（例如遮挡任务）：保留"记住"原则，改写为"历史通过运动状态起作用；视觉历史只在策略能从中恢复运动状态时有用"，
  并在附录 G.3"视觉历史"段改为如实报告。
- **SE(3) 历史增益不随延迟增长、或不在 $\ell^\star$ 附近出现**：这是对相应经验预测的反证。先检查延迟扫描是否真的推进了物理（附录 B.3），
  再检查跟踪误差是否主导（图 4c、表 S5）；若确实如此，把 5.3 的表述改为"增益主要来自 $e_{\rm loc}$ 或方向歧义"，并在附录 A.7 说明。
- **坍缩图（图 4a）不成立**（不同任务/速度的点不落在同一曲线上）：如实报告 Spearman $\rho$，把"预测每个策略在何处失败"弱化为"预测趋势方向"，
  并检查 $\varepsilon$（表 S3）是否估计偏差。
- **SE(3) 未来不优于点轨迹**：把"目标需要 SE(3)"弱化为"目标需要度量化、足以确定接触点的表示"，SE(3) 作为其紧凑形式；Kabsch 拟合行（表 S11）可支撑"刚性先验"的说法。
- **在线读取预测反而有害**：选 `QthreeCase=3`，并在 5.3 "行动"段说明原因（预测误差通过 $\mathcal F\to\mathcal A$ 传播；引用表 S9 的干预）。
- **区间跨越实际意义阈值（模棱两可）**：用"在本设置下未观察到可区分的差异（$\Delta$ = x，95% 区间 [a, b]）"，不要写"相当"或"更好"。

## 3. 填数工作流

占位符有三种，编译后的 PDF 中都以品红色显示：

- 文本：`\fillin{...}`（方括号内为提示，如 `XX.X`、`name`、`values`、`confirm`）。
- 表格：`\resultplaceholder`（品红色破折号）。破折号按典型数值 `00.0` 的宽度占位，因此当前表宽和版面已接近填数后的样子；
  格式更宽的列带有模板，如 `tables/supp_per_task.tex` 差值区间列的 `\resultplaceholder[{+00.0 [00.0, 00.0]}]`、
  `tables/supp_real_ci.tex` 的 `\resultplaceholder[00.0 {[00, 00]}]`、`tables/supp_predict.tex` 位姿误差列的 `\resultplaceholder[{00.0/0.0}]`。
  填数时把整个占位（连同方括号模板）替换为数值。
- 图：`\figplaceholder`（品红边框的方框，内写详细规格）。

生成待填清单（按文件、行号列出每处待填的提示、它前面的原文和所属的开关分支，另列图占位与每张表的待填格数）：

```powershell
python scripts/list_fillins.py --markdown tmp/fillins.md        # 英文
python scripts/list_fillins.py --zh --markdown tmp/fillins_zh.md # 中文审读稿
```

规则：

1. **同一数字在三处一致**：表格 → 正文 → 中文稿同一位置。`scripts/check_build.py` 会报告中英文之间的数字差异，以及开关分支、待填项、标签、引用和表格不对应之处。
2. **单位与格式**：成功率保留一位小数并带 `\%`；差值写"points / 个百分点"；区间写 `95\% interval [a, b]`；
   时间写 `\,ms`；表中最佳值加粗（`\textbf{}`）。
3. **只填当前开关选中的分支**。未选分支里的 `\fillin` 不会出现在 PDF 中，但 `list_fillins.py` 会列出（它扫描源码）；切换开关前先把对应分支填好。
4. **图**：把 `\figplaceholder[...]{...}{...}{...}` 整段替换为 `\includegraphics[width=...]{figures/xxx.pdf}`，保留原来的 `\caption` 与 `\label`；
   图注中的 `\fillin` 一并填写。
5. **表宽与公式宽度**：填数后重新编译。`preamble.tex` 已把 cvpr.sty 默认的 30pt 溢出容差改为 0.5pt（只影响警告，不改版面），
   因此任何超出栏宽的表格、公式或文字行都会出现在日志里，并由 `scripts/check_build.py` 报告（`--strict` 时报错）。
   超宽时先缩短列名或减小该表的 `\tabcolsep`，不要把表格字号缩到 7pt 以下。
6. **正文页数与声明**：`check_build.py` 检查正文及图表不超过第 8 页、声明位于正文后和参考文献前、A–G 编号及引用覆盖；声明与参考文献不计入正文页限。
7. 投稿前：

```powershell
./scripts/build.ps1 -Check
python scripts/check_build.py --final --strict   # 任何待填格、待填文本、超页、推迟的浮动体、未定义引用都会报错
```

## 6. 新框架要求、旧计划中可能缺少的实验（按优先级）

1. **实时协议 + 共享执行器**（附录 B.3）：所有方法按各自实测延迟推进物理、每 100 ms 重规划、按生效时刻执行、丢弃过时指令；
   并做三种协议对照（暂停物理、等延迟、原生执行器，表 S23）。这是审稿人质疑"延迟对比是否公平"的直接回应。
2. **延迟扫描下的历史变体（图 4b）**与**静止目标场景**：直接检验"领先时长 × 运动"项；所有方法的延迟扫描（表 S24）给出首图右侧数据。
3. **坍缩图（图 4a）**：记录首条指令生效时的领先时长、目标速度、任务容差与成功结果，计算未补偿运动/容差。
4. **输入对齐的基线**：π0.5+SE(3)、DynamicWAM+SE(3)（附录 F.1 的注入方式），以及 SE(3)-WAM CV 输入与卡尔曼拦截器；用于区分输入条件与表示的影响。
5. **间隙扫描（图 4e、表 S12）+ 各网格 $e_F$ 测量**：决定 `\QtwoCase`。
6. **耦合程序 × 延迟（图 4f、表 S14，含 R1 的两种部署）**：决定 `\QthreeCase`（开发集结论已出，见第 2 节；留出集与延迟扫描仍需做）。
7. **不使用物体模型的 SE(3) 历史**（WildDet3D 逐帧三维框与对称轴对齐，附录 C.2）与跟踪器精度表（表 S5）、位姿噪声注入（图 4c）：检验物体模型这一输入条件的影响。
8. **训练时延迟采样** $\ell\sim U[0,250]$ ms 与**相对上一指令位姿的增量**（附录 C.4）；时域 ±50 ms 错位与按控制步计领先时长的消融。
9. **DROID 提升的新流程**（场景流取 PointWorld 发布的 DROID 三维轨迹与优化标定；目标：指令物体 → Grounding DINO → SAM 2 → WildDet3D 度量三维框，
   因果输入与离线标签两条路径）与**接触后屏蔽世界标签**对照（表 S16）；旧 MoGe-2/DPFlow 标签只作标签质量对照。
10. PUMA 基线（DOMINO 自带方法）；记录各基线的训练与部署适配（表 S17）；DOMINO 的等级与 MS、LIBERO/DOMINO 的有效位姿比例。
11. 真机：传送带抓取的训练/测试物体实例与采集时段分离，三档带速标定，180 次共同试验键分为三块、对应三个微调种子；报告二项分布区间与按试验键自助法得到的配对差区间。
